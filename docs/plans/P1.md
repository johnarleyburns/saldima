Source: spec _Roadmap_ P1 and _Signup, billing, domain and login_; Design
_Data model_, _Routes_ and _iPhone app design_.

      password + TOTP, owner setup, login/logout, `/app` forwarding.
- [x] **Local e2e harness** (merged #23): alice/bob setup, TOTP, logout/login
      on all Playwright projects, isolated state.

      merge after unit/runtime/e2e guards; staging is reserved for release
      candidates.
- [x] **Scannable TOTP**: enrollment renders an inline QR code; the text

- [ ] **Stripe test-mode signup** (P1-2): Checkout, signed webhook, KV tenant,

      charts are seeded during owner setup.
- [ ] Opening balances (P1-3).

## Exit criteria

- [ ] A new customer signs up with a Stripe test card on staging and reaches a
      provisioned book.
- [ ] The insurance-agency template produces the agency chart.
- [ ] Account create/edit/move/hide round-trips to desktop GnuCash through the
      oracle.
- [ ] Unit, workerd and Playwright suites green; the iOS track can build the same
      templates offline.

## Decisions and open questions

- Password + TOTP is the first sign-in method; passkeys follow.
- TOTP secrets are encrypted with a key derived from the Worker `MASTER_KEY`
  secret and tenant ID. The spec's wrapped per-tenant key is the target.
- PBKDF2 is capped at 100k iterations by Cloudflare WebCrypto; this is the
  current platform maximum.
- Email provider still open; Stripe test keys still human-supplied.
- Setup is bootstrap-only: the `SETUP_TOKEN` secret is removed after the demo
  owners exist.
